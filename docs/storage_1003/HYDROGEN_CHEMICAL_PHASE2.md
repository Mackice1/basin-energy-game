## 已核实当前边界

目录目前27类，没有甲醇厂、合成氨厂、独立电解制氢厂或独立气/液/固储氢装置。`hydrogen_storage_system` 是电解/地上储氢/燃料电池成套返电系统，只有AC双向端口，库存为氢LHV等效MWh。质量仅按33.33kWh/kg换算，不是可外送的H₂物质网络。现有质量端口 `water_steam` 专用于闭式蒸汽循环，不可直接改名承载氢气、氮气或CO₂。

现有模型的电能、固定温区热能、蒸汽焓流与库存审计可以复用，但没有化工原料库存、组分流或化学计量约束。仅复制电池方程、改罐子形状，无法正确表示液化电耗、蒸发损失、固态解吸热或醇氨物料消耗。

## 最小完整实现范围与次序

### 2A：先贯通气态氢的真实物质链

一级成套设备：水处理/电解制氢站（包含整流和净化）、地上气态压缩储氢站（压缩机与瓶组）、燃料电池返电站。它们是可独立放置的整站，不把泵、阀、单个电堆堆进一级目录。

- 新建 `material_h2_gas`、`material_water` 物质载体，kg/s流率与kg库存；每个端口显式species、phase/grade、方向和流量上限，与AC/MW、热/MWth严格区分。
- 水供应是显式有限上限/库存的资源边界，不能凭空无限水。电解站按实际得到的AC电量及水量共同限产；水消耗与H₂/O₂生成按化学计量记录。氧气最小实现可明确作为无收益边界排出并记账，不假造售氧收入或免费回能。
- 压缩站按进入的实际H₂质量扣压缩电耗，压缩功率不足就限流；储氢kg库存、最大充/放kg/s、泄漏质量及LHV能损逐步守恒。可用压力等级是接口约束，不冒称动态真实气体压力仿真。
- 燃料电池输入H₂、输出AC，耗氢受实际库存、端口、燃料电池功率和下游接纳共同限制。先把未利用热明确计作排散，不免费接入热网。
- 已有集成H₂返电站仍按原存档原逻辑运行，不自动拆成多站、复制库存或重复计入新氢网。详情明确“集成教学系统”；新物质链为新类型。

验收终点：风电→电解/压缩→气态库存→燃料电池→负载；断水/断电/满罐/空罐/断管/下游不接纳均停止相应过程；保存加载保留kg，优化结果与实时运行及独立审计一致。

### 2B：液态与固态储氢必须有不同转换约束

- 液氢站是“液化+真空绝热储罐+气化供氢”整套装置。气态H₂入口、气态H₂出口（内部明确液相库存）及AC液化电耗，液化能力限制kg/s，等效蒸发质量按实际库存衰减；蒸发氢若无已建模回收机组就记为边界损失，不免费返电。气化所需热必须有计量热源/辅机假设，不能混作免费的高品位过程热。
- 固态首选明确的一类可逆金属氢化物整套装置，不把全部“固态”视为同一种材料。具体材料、允许温区、吸放氢热需求与速率根据供应商/研究实证核查后确定。吸氢需排热、放氢需足够温级的热输入；没有热源则不能按电池倍率自动放氢。若不能建立对应固定温区接口，该子型保持未启用而非假装可用。
- 两者都有与气态不同的真实照片参考、容量占地和辅机布局，外观跟随物理边界。液氢低温绝热容器不等同常温高压球罐；金属氢化物采用材料床/换热模块参考。

### 2C：合成氨与电制甲醇两套一级生产厂

复用2A氢气网并增加有限资源/原料端口，不重写电热调度主体。

- 合成氨成套厂：H₂与N₂入口、AC及必要热/冷公用工程、NH₃产品输出/有限缓冲库存。最小阶段配套成套制氮站（空气边界明确，实际制氮需AC电量）或有限外购N₂资源边界，不能空气自动变成免费高纯氮。化学计量 N₂+3H₂→2NH₃；按反应进度同时限制两原料、产能、电耗和产品接纳。
- 电制甲醇成套厂：H₂和CO₂入口、AC与过程公用工程、CH₃OH产品及水副产物流。最小路线限定CO₂加氢：CO₂+3H₂→CH₃OH+H₂O，必须有有限CO₂来源/进口资源边界；未建碳捕集模型时不冒称自动从空气免费捕碳。不支持没有碳源的甲醇生成。
- 产物先进入有容量限制的罐区/产品交付边界，不立刻充当“电量”。不在本最小阶段加入醇氨裂解、直接返电或复杂市场经济。所有副产物/排散及化学能变化入账；未实现余热回收时明确排散，不能输出未结算热。

## 尽量复用现有架构

新增纯函数 `material_dispatch.gd` 和组分/物料计量目录，不把H₂塞入现有`water_steam`闭式回路。电侧调用沿用`network_dispatch.gd`的实际电源/变电站/线容量路径；热侧沿用现有温级匹配。设备过程用一个受约束的吞吐量变量同时决定AC需求、物料耗用、产品和损失。必须联合限流，禁止先生产再补扣负库存。可用两阶段提议/提交：提议需求→现有电热分配→按所有实际供给取最小吞吐→重新核对并一次提交；若回馈未收敛，保守限流/拒步，不能以迭代误差创造物料。

优化器在当前LP/MILP生成器增加每设备过程吞吐变量、每物种库存方程、AC/热消耗系数和端口容量；继续采用现有GLPK及独立Godot结果审计。不得把实时缺少的物料约束仅写在优化端，反之亦然。旧快照/存档保留明确版本兼容，新类型只允许新schema；旧H₂LHV库存不自动换算复制成独立气库。

单独做按H/C/N/O元素的进出库存守恒与LHV/电/热账本，单步、累积、回路、恢复、篡改优化结果均测试。真实工艺能耗、负荷范围与材料参数待官方资料核查后作为明确教学参数，不在设计文档中编造工程性能。

## 审阅附录：最小闭环、文件责任与验收契约（2026-10-21）

本附录来自对当前 `device_catalog.gd`、`network_dispatch.gd`、`thermal_dispatch.gd`、`save_validator.gd`、`optimization_controller.gd`、`world_game.gd` 及 Python 调度器的只读审阅。只更新设计文档，未实现下述 API、设备或求解器。当前段 GUI 验收交接后才能进入实现。阶段二不得承诺任意化工网络、非线性压力/相平衡或复杂新求解可以直接完成。

### A. 2A 精确最小范围

第一份可验收增量限定为一条完整功能链：**有限合格液水边界 → 电解制氢整站 → 地上压缩气态储氢站 → 燃料电池返电站 → 已接线的实际电负荷**。以下 kind 名称是待冻结的实现契约建议，不是当前已存在的类型：

- `water_supply_boundary`：显式水源节点，合格液水库存 kg、最大出流 kg/s、单向水端口；库存耗尽即停止供水。2A 没有自动补水、天气降水变纯水或每时段重置库存。水处理辅机可计入电解整站净电耗，但不声称已模拟原水净化回收率；若以后引入原水，必须另记处理损耗/排水。
- `electrolyzer_station`：一个 AC 输入、一个水输入和一个气态 H₂ 输出；整流/净化辅机包含在净 AC 比耗内；按实际产氢量同时扣电、扣水、生成氧。不能同时再用旧集成站的充电效率重复扣同一道电解损失。
- `hydrogen_gas_store`：一个气态 H₂ 输入、一个气态 H₂ 输出和压缩 AC 输入；内部只有有限 H₂ kg 库存。入口压缩耗电与实际充入 kg 同步，出气包括明确的调压整站边界。不做地下储氢、真实气体压强瞬态或膨胀发电。
- `fuel_cell_station`：一个气态 H₂ 输入和 AC 输出；净返电参数含燃料电池/逆变器/约定辅机，按实际负载接纳量限耗氢。2A 不向电网外送、不充其他储能、不回供电解或压缩辅机，避免新增跨能量循环和与旧储能策略不一致。

2A 只开放上述有向物料路径，可共享有限水源和管路容量，但不开放任意反应循环、气库互充、电解直送燃料电池或同一气库同段充放。气库先扣步初库存泄漏，再执行本段单一充/放模式，新充氢不能在同段穿库返电。电解/压缩使用实际连接的风/PV余电，放在既有电热负荷和既有储能优先策略之后、弃电/外送之前；燃料电池只补足既有优先电源服务后剩余的电负荷。新规则只影响含新物料设备的场景，不重排旧场景结果。

氧气先按无收益排出边界记账；燃料电池的空气侧氧输入、水产出和排热也必须记账。空气是明确的外界入口，不是密闭循环的免费物料，氧摄入受燃料电池实际吞吐/整站额定能力约束；无需在 2A 增设纯氧罐。燃料电池产水采用锁定的输出物相并作为排出边界，暂不回流水源，避免隐藏无限循环。DOE 明确电解消耗水产生氢/氧、氢燃料电池使用空气中的氧并产生水和热。[DOE 电解](https://www.energy.gov/cmei/fuels/hydrogen-production-electrolysis)、[DOE 燃料电池](https://www.energy.gov/cmei/fuels/fuel-cells)。

2A 完成标准包括实时、保存恢复、Python 优化和独立 Godot 审计全链一致；只做实时物料而优化静默忽略它，不算完成。实现过程中如优化尚未接通，应在快照入口明确报“物料设备优化尚未支持”，绝不能过滤新设备或退回纯电结果。

### B. species、单位与有限资源契约

建议新增一个版本化只读物料 profile，统一记录 `species_id`、原子组成、摩尔质量、参考物相/参考态焓、LHV 指标、过程反应系数和公用工程比耗。Godot 与 Python 使用同一份经验证的静态数据；审计从可信 profile 重算，不能信任结果文件回传的摩尔质量/反应系数。默认工艺性能仍需核实来源，不能把下面的字段建议当作已批准数值。

- 管路保持 `from_port`、`to_port`、`carrier`、`unit`、`grade_id`，新增明确 `species_id`、`phase_id` 和 `mass_flow_capacity_kg_s`。2A 使用已有设计中的 `material_h2_gas` / `material_water`，且必须与 species/phase 一一一致；不能用 carrier 写 H₂、species 写 CO₂ 的矛盾组合绕过验证。`water_steam` 与它的封闭 Rankine 回路完全不变。
- 端口方向与 species、物相、交付等级均须匹配；压力等级只是已核验整站的接口标签。低压转高压必须经过有耗电的压缩整站，不允许改线标签完成压缩。管内暂不储料，2A 管损为零；以后启用管损时必须增加对应 species 的边界损失，不能复用电阻损耗名义消失质量。
- 连接去重键应包含两端 port、carrier 和 species，而非只比较设备 ID。若端口允许分流，全部连接之和仍受该端口总额定流量限制；单边没有超限不代表共享端口没有超限。后续同一对设备有热边和物料边时，必须先按显式 carrier 分派，再核对 species/端口，不能只凭设备 kind 提前选中 Rankine/热边解析分支。
- 建议新库存形状为 `state.material_inventory_kg = {species_id: kg}`，每种设备由 profile 限定精确允许键集合。气库只允许 H₂，水源只允许 H₂O；转换器无库存时不得凭空新增缓存。后续产品缓冲可扩展相同结构，液氢/氢化物内部相态由固定 profile 区分。
- 每个源节点有独立稳定 ID，所有消费者共同扣同一份库存和出流上限。CO₂、N₂后续复用有限源逻辑，而不是复用当前每时段重置的 `fuel_supply.max_input_mw`。2C 最小采用有限外购 CO₂/N₂ 边界，先不添加 DAC/空分求解。
- 原料/产品初始库存是显式初始条件，不属于本步生产。改变容量不得静默裁掉已有库存；改变 species/profile 不得把存量水重标成氢。补料、交付、带料拆除必须有显式物料边界记录，累计账本不因删设备清零。
- 单位关系固定：流量 kg/s 乘 `dt_s` 得 kg；比耗 kWh/kg 乘 kg/s 再乘 3.6 得 MW；MJ/kg 乘 kg/s 得 MW。不得把 kg/s 当 kg/h，或把 kg 库存混进电储能 MWh/SOC 合计。`dt=0` 时所有物料转化、泄漏和资源扣减均为零，负值/非有限 dt 拒步。

### C. 热力学与化学计量不可省略的边界

**LHV 是燃料能量指标，不等于任意物相下的完整反应焓。** 新模型应同时给出物料/元素账本、AC账本、物相一致的焓/热账本及另列的LHV库存指标，不能把“AC输入减产氢LHV”直接作为可向热网输出的热。NIST 给出的水标准生成焓，气态为 −241.826 kJ/mol、液态为 −285.830 kJ/mol；两者不同。因此液水进电解、燃料电池水蒸气排出或冷凝液水排出，必须采用同一锁定参考态并显式处理相变项。[NIST 气态水](https://webbook.nist.gov/cgi/cbook.cgi?ID=C7732185&Mask=1)、[NIST 液态水](https://webbook.nist.gov/cgi/cbook.cgi?ID=C7732185&Mask=2)。这些参考值不是整站工程效率或用户可调工艺性能。

- 2A 推荐锁定液水进料及一种明确的燃料电池产水物相；无外部热输入的低温电解 profile 必须满足相应反应焓与非负排热约束。不要以较高 LHV 效率参数隐式引入未建模环境热。所有排热仅进入边界账本，默认不能回收售热。
- 压缩耗电单列，不增加 H₂ 化学 LHV。固定压力级整站采用净 kWh/kg 参数及散热/调压边界，不冒称模拟压力可用功；气库泄漏同时扣 kg、携出相应化学能，不能只减 SOC 不减质量。
- 液氢内部仍是 H₂，液化不是化学反应。液化电耗、液化速率、低温库存、蒸发损失以及气化热分别约束；不能用一个“电池放电效率”代替。气化所需热可来自显式限流的适用温级热源或明确计量的环境换热边界，不能把环境吸热当免费高温工艺热。漏热导致的蒸发与气化耗热不得重复计算；无回收模型的蒸发氢直接记带化学能的排出。
- 金属氢化物先冻结一个具体材料家族与可逆反应 profile，核实工作温区、容量基准、吸/放氢速率、热需求及辅机/冷却边界。吸氢放热需足够排热能力，解吸需合适温级热且热不足就限流；绑定态与游离 H₂ 的焓差必须记入储存状态能量，不能把相同吸/解吸反应热两端都当免费收益。资料不足或现有温级不适配时保持未启用，不借用热水端口虚构可放氢。DOE 强调材料储氢性能取决于材料、压力、温度及其反应热力学，并非通用固体罐。[DOE 材料储氢](https://www.energy.gov/cmei/fuels/materials-based-hydrogen-storage)。
- 氨和甲醇使用单个非负反应进度 `extent_kmol_s`：电解 `2 H₂O → 2 H₂ + O₂`；燃料电池取逆反应；氨 `N₂ + 3 H₂ → 2 NH₃`；甲醇 `CO₂ + 3 H₂ → CH₃OH + H₂O`。各 species 质量流等于反应系数乘摩尔质量乘同一个进度。摩尔质量应由同一组原子质量推导，不能一处用近似 9:1 水氢比、另一处用精确分子量再要求严格原子闭合。
- 氨/甲醇产能、各原料供给、AC、所需温级热、排热能力和产品/副产物接纳均约束同一进度。净外部供热需求与反应放热必须分开：不能因为反应放热就宣布整站不需公用工程，也不能把同一热量既计产品化学能又计输出热。产品满罐即停反应；甲醇副产水必须储存或明确排出，不能无去向消失。最低实现不提供氨裂解、甲醇返电或自动市场收入。

### D. 实时原子提交与优化等式

当前 `network_dispatch._allocate()` 会立即扣资源、写电线流量和设备报告；所以“先给电解分电，发现水不足后缩产”并不安全，除非完整回滚多分的电和线/站容量。现有电、热、Rankine 耦合只能作为实现范例，不能直接假定它们支持任意化工联立。

2A 建议采用受限拓扑下的事务式整链预约，不引入实时外部求解器：

1. 从步初有效库存、泄漏后库存、实际 AC 路径及未使用资源建立候选整链；充氢事务同时包含水源、电解、管路、气库余量及压缩电耗，返电事务同时包含气库、管路、燃料电池和实际负载路径。
2. 在资源副本上为一个候选吞吐预约所有路径；**同一事务重复经过的线、站、共享水源等容量必须先合并系数**，不能每个子设备各享一次全部余量。电耗按设备终端实收计算，源端还须承担既有线/站损耗。
3. 取所有物料、库存、功率、端口和接纳约束的共同可行吞吐后重新构造完整预约；成功才一次写入报告资源和拟议 `next_states`，失败则整笔无副作用。禁止依赖多轮“补电、补氢”直到看似收敛；不能证明预约一致就保守拒绝该事务或拒步。
4. 对整步原始输入、所有物料边界、AC路径、热账本和状态更新独立审计；仅当 `report.valid` 且所有域审计通过时，世界层统一提交库存、累计账本和仿真时间。无效报告、预览、取消优化均不改活状态。

统一库存方程建议为 `m_next = m_before * exp(-leak_per_h * dt_h) + (in_kg_s - out_kg_s) * dt_s`。泄漏作用于步初库存，新增入料在本段末入账；这是明确的离散时间假设，不宣称有入流时任意拆分步长仍完全等价。储氢充放二元互斥、出流不得超过泄漏后步初量；水/CO₂/N₂资源没有自动再生。反应源项在对应设备物料守恒中由同一个反应进度生成，不能把耗氢写成库存凭空损失。

Python 在相同模型下增加 species 线流、过程吞吐、各节点各 species 库存和必要的充放二元变量；AC/热/物料约束同时联立，固定系数可保持线性，不引入压力非线性或化学平衡求解。其最优调度不要求逐步等于实时贪心调度，但必须使用相同初态、可行域、单位、边界、过程系数、泄漏时序和独立审计。多种同等最优方案也不能被误判为跨语言失败。

**目标函数是必要接口，不是事后补 UI。** 当前 `build_model()` 的顺序是电/热未满足量、外送、储能吞吐，再加热过程/燃料目标，没有氨/醇生产目标。在此基础上直接添反应变量会倾向于不生产产品，也不会自动满足用户的期末氢储量需求。

- 新物料快照显式提供每个气库的期末 kg 下限（可指定恢复初始）及后续产品交付 kg 目标/速率/优先级；不把所有库存统一当电池 SOC，水和原料库存也不应默认强制恢复初始量。
- 2A 建议保留电/热服务首目标，以显式可行的期末氢量下限作为约束；下限不足应说明不可行，不静默删约束。没有期末目标且未来不需返电时，优化不产氢是合法结果，不能宣传自动获得储氢最优收益。
- 2C 明确增加产品欠交目标阶段，位于外送之前、既有电热服务之后；产品质量先按声明的目标归一化或明确权重，同量 kg 氨与甲醇不能任意等价，也不得把 kg 直接加进 MWh 服务目标。库存恢复、交付目标和严格/软约束的语义应同时显示在基准比较中。
- 优化仍是只读预测；现有 `optimization_controller.gd` 明确不将方案写入实时世界。接口、超时/取消、不可行说明及原始输入审计要延续，不能因新模型增加而暗中改为自动应用。

### F. 必须有的独立验收样例

1. **单位与计量**：固定质量进度的电解、逆反应、氨、甲醇四组反应各自验证 H/C/N/O 原子守恒、总质量、kg/s→kg、kWh/kg→MW；改变 H₂O 物相只影响焓，不能改变原子组成。
2. **2A 正常闭环**：风/PV供电时产氢入库，之后无发电且有负荷时返电；逐步核对水减少、氧排出、H₂库存、压缩电、AC线损、燃料电池氧摄入/水排出、排热和泄漏。初始氢库存可返电但不计为本段可再生发电。
3. **每个单独瓶颈**：断水、无AC、压缩电不足、满罐、空罐、断管、端口限流、线/站限容、下游零需求，以及多个电解站争同一水源。每种情况下都不能负库存或先生成后扣回；共享资源不能重复占用。
4. **事务失败**：预约最后一步失败后，电线流、站余量、水量、气库、累计量和时间均无半笔更改；审计拒绝、预览、优化取消、过期 revision 同样不动实时世界。
5. **边界数值**：零步长、负/NaN/Inf、极小流率、大 dt近耗尽、容量正好相等、泄漏接近全空、充放互斥。验收使用按量纲设定的绝对+相对容差，不用单一宽松残差掩盖 kg/MWh混淆。
6. **保存兼容**：旧 schemas3–13固定夹具及旧集成H₂结果不变；旧schema拒新kind/新状态；新schema round-trip保留资源/氢/产品kg与累计边界；未知 species、负库存、超容、错物相、篡改 profile、换 species带料、删设备漏记物料均拒绝或按显式边界规则处理。
7. **优化对齐**：同一冻结输入跑实时基准与真实GLPK预测，再由Godot从原始输入审计优化报告；比较物理可行性/守恒而非要求贪心与最优轨迹相同。分别测试期末氢下限、产品欠交顺序、不可行资源不足、零目标不生产、错误源端电能归属与同段自举回路。
8. **主动篡改**：同时修改报告中的species、流向、端口容量、反应进度、进/出料、质量库存、LHV、热/相态、路径损耗、自报balance=0和遗漏next_state；独立审计必须仍能从原始图与profile抓到不一致。
9. **2B独立门槛**：液氢无液化电不充、无约定气化热不出、蒸发失质量和化学能；氢化物无适温热不放、无排热能力不充，物相/绑定焓不重复计能。材料来源/温级尚未核实则没有该建造按钮。
10. **2C独立门槛**：无N₂不产氨、无CO₂不产甲醇；所有原料分别成为瓶颈；NH₃/甲醇/副产水接纳不足同一个反应进度归零或限产，不能丢弃多余原料；原料耗尽后跨步和恢复保存均不再生成产品。

实施顺序：先冻结本附录的 profile/状态/事务/目标契约和测试夹具，再完成2A各域与端到端验收；随后分别核实并实施2B各子型，再做2C。可并行研究/测试，但任何未接通守恒和优化的设备都不标记为已交付。
