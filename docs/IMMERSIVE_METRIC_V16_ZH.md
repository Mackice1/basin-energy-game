# V16 · 米制设备与沉浸式电热站

更新：2026-10-15。适用当前 `Basin02` 源码；Godot 4.6.3 Standard / Compatibility。本文覆盖 V16 新增的尺寸、资产、迁移与验收边界。既有电热调度见 [首批电热链](THERMAL_STAGE1_USER_ZH.md)，厂站操作见 [厂站两层指南](STATION_HIERARCHY_ZH.md)。历史文档的示意比例、schema/model 和测试数字不替代本页的当前说明。

## 1. 本轮完成了什么

- 新游戏采用 `metric_v1`，统一 **0.1 世界单位 = 1 米**。基地和站内使用同一换算，进入站内只改变观察相机，不改变设备尺寸、布局坐标或库存。
- 电热水锅炉、双罐储热、隔离换热器及电热站院区接入 Blender 制作的 GLB。米制光伏按组件片数绘制，电池按箱数、中压单元按模块数排布；不是把一个模型随总容量拉大。
- 站内具备设备、管线、维护通道及近距离相机。管道弯头、管托、设备自带管口等增加辨识度，但没有新建水力学求解器。
- 新存档写出 **schema 7 / model 16 / dimension_profile**。schema 3–6 读入时保留旧表示和原坐标，米制迁移需显式校验及确认，可撤销。
- 地貌不再以占位建筑方块表示；外部服务点使用环形标记。水源、交通、燃料接口明确标为“场地示意”，不冒充已接入调度的设施。

这是带统一米制几何的教学原型。厂家参考外形、教学运行限额和工程合规不是同一件事。

## 2. 米、占地与碰撞是怎样区分的

权威尺寸解析在 `scripts/spatial_dimensions.gd`。参数及尺寸使用米，进入视觉时仅换算一次。代码 `Vector3` 的顺序为 **X、Y高度、Z**；资产清单 `dimensions_m` 和下表采用 **长×宽×高**，不能按同一种数组顺序盲目比较。

- `body_dimensions_m`：模块组整体实体包络；`body_area_m2`：实体投影量。组件面面积、模块组含空隙的矩形包络、土地面积分开计量。
- `land_dimensions_m` / `land_area_m2`：包含排布间距及教学检修边带的安装区。
- `clearance_radius_world`：安装矩形外接圆的保守碰撞/避让半径；`land_envelope_area_m2` 为该圆面积，不能称作基础或建筑面积。圆形筛查会拒绝某些矩形本可容纳的紧凑布局。
- 风机另列基础、维护区及转子扫掠包络。18×18 m 基础和32×32 m 维护区为教学假设；转子半径来自设备直径，避让至少涵盖转子半径加7 m。转子扫掠圆不能算成基础面积。风机基础及检修板另按实际变换后的网格验证，米制表示需落入18×18 m / 32×32 m声明范围；GPU上传后的几何量化采用1 mm验收容差，最终专项1220项检查全部通过。
- 需求标记仅表示外部连接点，没有建模真实住宅或工厂，建筑占地为0；其交互间隔不能当真实用地。

视觉、放置预览、容量修改及读档校验共享这套尺寸。扩大容量导致增加模块时，需重新满足边界与间距；放不下会拒绝该操作。地形仍为有限点采样的禁建/坡度初筛，不代表逐点基础、叶片净空或消防验收。

## 3. 当前模块与来源边界

官方资料、引用链接和推导详见 [尺寸参考研究](DIMENSION_REFERENCE_RESEARCH_ZH.md)。该文包含设计建议，**不是所有建议都已经实现**；当前几何以尺寸解析器及 `assets/models/thermal_asset_manifest.json` 为准。

| 类别 | 当前单元 / 模块数量 | 参考与教学边界 |
|---|---|---|
| 电热水锅炉 | 4×2.5×2.5 m；`max(1, ceil(电输入MW/2))` | ECOTHERM 2000 kW型号外形参考；2 MW是电输入，默认效率0.98时热输出上限1.96 MWth。 |
| 双罐储热 | 8.5×5×7.635 m；`max(1, ceil(容量MWhth/4))`，每模块2罐 | 4 MWhth、约125 m³名义水量及90/60°C温区为教学设计，没有宣称对应厂家标准罐型。实际资产顶部附件达到7.635 m，不能继续用研究草案的7 m替代。 |
| 隔离换热器 | 3×2×1.8 m；`max(1, ceil(容量MWth/2))` | Alfa Laval M10系列仅作外形量级参考。泵阀底撬和2 MWth额定为教学假设，未按板片数、压降及工况完成厂家选型。 |
| 电池 | 6.058×2.438×2.896 m；`max(1, ceil(E/5.015), ceil(P充/2.5), ceil(P放/2.5))` | Sungrow ST5015kWh-2500kW-2h箱体参考。默认10 MWh、3/3 MW为2箱；仍执行原来的10 MWh可用库存和3 MW总功率，不能叠加成10.03 MWh或5 MW的运行设备。 |
| 中压变电单元 | 6.813×5.538×2.941 m；`max(1, ceil(容量MW/2))` | SMA MV Power Station 2000SC带平台包络参考；2 MVA按功率因数1映射2 MW为简化。原产品含逆变与中压设备，游戏不重复增加逆变容量，也不宣称复刻厂家内部构造。 |
| 光伏 | 每片2.278×1.134×0.035 m，550 Wp；`ceil(MWdc×10⁶/550)` | Jinko JKM550M-72HL4-V F3参考。默认1.2 MWdc对应2182片、1.2001 MWp参考装机；控制额定仍为1.2 MWdc。 |

通用模块间距2 m、四周边带2 m是当前教学假设，与研究表中的部分建议预留不同。低于一个参考模块容量仍保留完整单元，按原参数降额使用；模块组只共用一套设备端口、容量和库存，不产生额外调度节点。

### 光伏不是“12片等于1.2 MW”

当前实际排布使用25°倾角、1.2 m列距、5 m排距、四周4 m边带。默认2182片排成96列×23排，末排70片；面板总面面积5636.655864 m²，安装矩形约123.134×120.079 m，约14785.85 m²。这是教学排布，不保证特定纬度、季节下无阴影，也不是施工总图；与研究文档的52列×42排示例不同。

正常规模绘制全部等尺寸组件并合批；超过32768片时有行带式简化表示，组件数量、布局解析和包络仍保留，不缩小世界尺寸。碰撞仍使用完整安装区的外接圆。旧档的面积字段不能被无提示重新解释成新用地面积。

## 4. 电热站：外部院区与内部净区

电热站是**80×60 m院区，4800 m²**，内部净布置区为**48×48 m，2304 m²**。内区属于外区，不重复相加。外部保守避让圆半径50 m，面积约7854 m²，不能再当作建筑实体面积。院区模型最高附件为9.1 m；它是露天厂区和附属建筑的组合，不是80×60×9.1 m实心厂房，也不是把高储罐塞进标准集装箱。

米制示例内部采用三角形布局，以下为站内世界坐标 `(x,z)`：

- 锅炉：`(-1.0, -0.7)`，对应 `(-10, -7)` m
- 双罐储热：`(0.9, -0.6)`，对应 `(9, -6)` m
- 换热器：`(0, 1.0)`，对应 `(0, 10)` m

外部GLB是80×60 m教学总图及厂站标识，内部固定示意罐与外壳不作为额外物理设备；实际内装数量、容量和库存以站内设备清单为准。全场占地只计厂站外部，站内设备用地不再与院区相加。该外观不是随全部内部设备逐项重建的施工级内外投影BIM。

这些位置分别按完整安装/避让包络验证。内部可建设、选择和移动三类设备，外部端口继续映射到真实内部设备。外观没有另造一座会发电或产热的设备；旋转、平移、缩放相机不推进时间、不修改库存。

## 5. 资产与场景审计索引

Blender源文件：`art_source/blender/thermal_assets.blend`；生成器：`tools/build_thermal_assets.py`；实际资产元数据：`assets/models/thermal_asset_manifest.json`。

| Blender场景 / GLB文件名 | GLB根节点 | 本次清单三角形数 | 关键标记 |
|---|---|---:|---|
| `electric_boiler` | `ElectricBoiler` | 3252 | `Port_ac_in`、`Port_heat_out` |
| `thermal_store` | `ThermalStore` | 6016 | `Port_heat_in`、`Port_heat_out` |
| `heat_exchanger` | `HeatExchanger` | 5112 | `Port_hot_in`、`Port_warm_out` |
| `thermal_station` | `ThermalStation` | 10008 | `Port_ac_in`、`Port_heat_out` |

GLB位于 `assets/models/<场景名>.glb`。清单记录 `visual_dimension_profile=metric_v1`、`world_units_per_meter=0.1`、根变换、包络和端口坐标；各资产声明 `visual_only=true`、`capacity_added=0.0`。`ThermalAssembly`为合并后的静态网格，`ProfileLabelAnchor`仅用于标签。运行时后端应为 `blender_glb`；资源缺失或端口不符时保留可诊断的后备表示，不能把后备绘制当成GLB验收通过。

运行场景主要名称：

- 基地外观：`ThermalStationFacade`
- 站内：`InteriorViewport`、`StationInteriorWorld`、`InteriorCamera`、`CivilYard`
- 内部设备：`InternalEquipment/InternalDevice_<id>`
- 连线显示：`TypedInternalConnections` 下的 `ACCable_<from>_<to>`、`HeatPipe_<from>_<to>`
- 电气模块组：`PhysicalModule...`、合批后的 `MetricModuleGeometry`；光伏合批为 `MetricPVField`
- 地图外部服务标记：`ExternalServicePin`，标记 `display_only=true`

`map.gd`的地貌标签只标地理名称，不再生成“地貌建筑”方块。电网仍是有明确容量限制的外部电力接口，其余水源/交通/燃料标记带“场地示意”。站内曲线管道及资产自带管道只显示已有连接/构造，不根据管长或直径新增能量、流量或损耗。能量计算仍只使用既有设备、线路参数和调度结果。

## 6. 存档兼容与显式迁移

| schema / model | 当前读取方式 |
|---|---|
| 3 / 11、4 / 12、5 / 14、6 / 15 | 保留 `legacy_illustrative`；旧坐标、容量、库存及连线继续保留，不自动缩放。 |
| 7 / 16 | 必须具有合法 `dimension_profile`：`metric_v1` 或 `legacy_illustrative`。 |

旧档成功载入后，保存会写出schema 7，但仍保留 `legacy_illustrative`，这不等于已经迁移米制。新游戏使用 `metric_v1`。不兼容已经丢失的旧V10，不能用此功能恢复丢失源码或存档。

在“尺寸说明”选择“校验并迁移为米制（不缩放原坐标）”：

1. 先在候选状态上切换尺寸配置，验证完整站内/站外包络、间距、边界、地形及既有存档约束。
2. 失败时说明原因，当前场景、坐标和库存保持不变；不自动压缩、不重排、不扩建院区。
3. 通过后仍须确认，才切换为米制外形和占地。保留原设备ID、连线、容量、库存及坐标，并建立撤销快照。
4. 撤销可返回原尺寸配置；载入、迁移及撤销后暂停。重复读取新存档不会再次转换坐标。

例如旧站内偏移12 world在统一尺度下是120 m，超过48 m净区，不能暗中乘0.1让它通过。当前只提供“保持原坐标，校验通过才切换”，尚未实现研究建议的自动扩大外站、迁移预览报告或重新排布向导；用户需先调整布局或另建米制示例。

## 7. 运行与气象说明同步显示

- 风机动画在非有限风速、低于切入或达到/超过切出风速时停止；运行区间内转速仍是示意，不可据此读取真实发电功率。
- 气象面板明确CSV尚未读取 `wind_height_m`，不能自动把10 m测量风速换算为轮毂风速。PV冷却复用相应风速是教学假设，不代表已经分别校正到组件高度。
- 设备直接功率优先于设备专属气象，再到全局气象及未绑定字段的教学天气；设备专属气象不代表整场实景天气。
- 全局状态明确未绑定出力字段仍取教学值，未导入云雨时其状态为未知；仅导入雨强不会自动变出实测辐照或额外扣雨损。
- 位置与日历用于太阳位置近似，不能生成当地实测/预报天气。顶部“合成场址 / 教学模型”和资源边界说明保留。

### 云软件渲染的配对测量

[完整性能报告](../evidence/performance/COMPARISON_V16.md)及其原始数据比较独立解压的v7基线与冻结V16渲染候选。均为Godot 4.6.3 / Compatibility / llvmpipe，1440×900窗口、900×620站内视口、30帧暖机和60帧采样；采样无截图IO，物理仍为60 Hz。配对使用相同旧版 `legacy_illustrative` 快照和相机，运行倍率×1。两相机无关的正交size属性虽不同，但实际均为透视相机，投影矩阵已核验一致；整套数据和配对校验112/112通过。

| 旧版相同快照 / 相机 | v7中位 / P95帧时 | V16候选中位 / P95帧时 | v7→V16平均FPS |
|---|---:|---:|---:|
| 基地暂停 | 224.64 / 250.95 ms | 214.43 / 246.20 ms | 4.41→4.59 |
| 基地运行×1 | 227.59 / 256.23 ms | 216.37 / 237.32 ms | 4.35→4.62 |
| 站内暂停 | 276.02 / 300.40 ms | 98.60 / 119.42 ms | 3.62→9.87 |
| 站内运行×1 | 280.49 / 319.18 ms | 110.65 / 122.91 ms | 3.53→9.01 |

站内平均帧时分别减少约63.3%和60.8%，与停止重复绘制被站内界面遮挡的基地3D等渲染改动有关；没有降低物理更新频率，`advance()`积分函数未改。配对仍是整个应用开销，不能称作完全相同像素的纯渲染引擎基准。基地差异较小，单轮数据不足以证明可靠改善。

真实 `metric_v1` 新示例及三类站内GLB另行测量，**不与旧版示意比例直接相减**：基地平均4.20 FPS（暂停）/4.18 FPS（运行）；米制站内全景6.44 FPS（暂停）/6.09 FPS（运行）。这仍不流畅，也不是硬件GPU结果。没有进程级CPU隔离，驱动未确认VSync实际禁用；软件低帧率下模拟×1也不一定追上墙钟。该性能测试使用冻结渲染候选；后续风机基础/维护板包络修正和读档求解器ID修复已补做功能回归，不把它们称为已重新计时。具体源码范围见报告及候选源码哈希。

### 待验收与未实现

1. 桌面真实GPU上的帧率、帧时间分布、较大设备场景和交互响应。已有上述云软件渲染同条件对照，但不能外推成流畅体验或硬件GPU结论；后续补丁未重新计时，不能将冻结候选的数值当作最终包逐字节相同的基准。
