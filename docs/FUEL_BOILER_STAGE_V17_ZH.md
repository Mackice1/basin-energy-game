# V17：一台天然气热水锅炉与独立资源接口

2026-10-16。在 V16.2 冻结基础上只增加 `fuel_boiler`，接入既有电锅炉、储热、换热器和独立热需求。来源与尺寸详见 [设备来源](FUEL_BOILER_SOURCES.md)。

## 使用

进入电热站，点“燃气热水锅炉”建设，接入 AC 辅机电和 90/60°C 一次热水端口。基地右侧火焰图标打开独立燃料资源设置。新游戏燃料供给默认关闭、上限为零；建设设备不会增加资源。开启并设置供给后“应用”是一次可撤销编辑，取消只丢弃草稿，不改时钟、库存或历史账。

模板栏的“燃气＋电热联合示例”显式开启 1.5 MW_LHV 共享供给。9 台设备、11 条连接中包含 1 台燃气锅炉；示例整体可撤销。供应可以随时关停，不能通过缺电继续供热。

## 单位和守恒

- 燃料输入 F：MW_LHV；有用热 Q = ηF：MWth；辅机电 Paux = αF：MWe。
- 默认额定燃料 2 MW_LHV、效率 0.90、辅机比例 0.01 都是教学假设；辅机分母是燃料输入，不是热输出。燃料转换损失 `(1−η)F` 与辅机电散失分开列账，辅机不增加可供热量。
- 默认低位热值 10 kWh_LHV/Nm³；体积率 `1000F/LHV` Nm³/h。这里 Nm³ 约定 0°C、101.325 kPa，真实账单必须另核成分、温压和高低位热值口径。
- 默认 300 元/MWh_LHV 是教学价格，不是市场报价。成本率 `F×价格` 元/h；1.5 MW 输入对应 150 Nm³/h、450 元/h、1.35 MWth 热、15 kW 辅机和 0.15 MW 燃料损失。
- 所有燃气锅炉共享一个有限的瞬时供给上限，不能各自拿到完整供给。燃料、电网络、热路径、设备能力和可接收需求/储热空间共同限出力。
- 时段积分分别保存输入 MWh_LHV、Nm³、元、有用热 MWhth、燃料损失 MWh 和辅机 MWh。后来修改热值或价格不重算已发生账目。

## 实时与优化

实时采用确定性教学调度：可再生电锅炉、储热供热、燃气锅炉（优先可再生辅机、再电池辅机）、电池电锅炉。在有热路径及库存空间时，剩余天然气可通过可再生辅机向储热充热；共享燃料按可行机组公平分配并重分剩余额度。这是可审计的启发式，不保证最低费用。

GLPK 联立燃料、AC 辅机和热平衡，强制每台机组 Q=ηF、Paux=αF，并限制全部机组燃料总和。没有电、燃料或可接受热端时不得凭空出热或弃热。保留已有四级目标，燃料成本是第五级目标，不能宣称它凌驾于此前服务/能量目标。结果有独立守恒与资源审计；优化只对冻结快照求解，不推进实时世界或改写库存、撤销、存档。

旧 `boiler_electric_mw`、`boiler_heat_mwth` 及旧电锅炉损失账含义不变。燃气独立报告和累计账避免把两种锅炉混成同一种电耗。

## 尺度和保存

单模块真实米制 5×3×4.5 m，默认安装区 9×7 m；每 2 MW_LHV 添加一个等尺寸视觉模块，不压缩设备腾地。外形包含燃烧器、黄色燃气阀组、烟道和热水接口；原创 Blender 源、GLB 和独立清单一起保留。

当前写出 schema 8 / model 17，包含独立 `fuel_supply`、`fuel_energy`。旧 schema 3–7 仍可读，缺少燃料字段时用关闭供给及零燃料历史；保留原米制/旧示意配置和坐标。存在燃料的优化快照采用 schema/catalog 3，无燃料旧快照保持此前格式。

## 验证与边界

证据放在 `evidence/fuel_stage/`，模型专项在 `evidence/fuel_boiler/`。200 个旧场景的实时报告和优化快照与原 V16.2 归档逐字节一致；新专项包括缺电、断路、限供、多锅炉共享、储热上限、独立审计、撤销、旧档迁移和真实 GLPK。

资源接口目前是固定有限功率上限及单价，没有气库库存、逐时气源 CSV、气网压力、燃烧动力学、启停成本、最小稳定负荷、排放、安全设计或设备选型认证。它是热水锅炉，不含蒸汽、汽轮机或燃气发电。下一阶段应由用户选择一条设备链再扩展。

### 本阶段最终验收

完整固定回归：56 个 Godot 汇总、336,538 项检查，61 项 Python 测试，全部通过（`evidence/fuel_stage/validation/full_regression_final.log`）。原生 X11 鼠标/键盘实际操作另通过 12 项存档/计量断言（`native_validation.json`）：进站、选中燃气锅炉、聚焦、运行暂停、资源草稿取消、关供给、撤销、1024×768 窗口、建设预览取消和 F10 保存；没有用程序调用冒充这些原生输入。图形控制器捕获及新进程读档/GLPK另有独立证据，其调用方式在记录中标明。

本轮不声称提帧。新设备包含 4,168 三角形；云端软件渲染仍可能低帧，实际鼠标测试使用较长按下等待。没有为视觉或帧率降低物理采样、改变尺寸或省略辅机依赖。

图形捕获通过 42 项，捕获存档的新进程读回与实际原生鼠标存档的新进程读回各 18 项；两者真实 GLPK 均通过独立审计且世界、撤销和存档字节不变。最终十张截图及详细摘要见 `evidence/fuel_stage/validation/`。截图时云 llvmpipe 瞬时观察 4–6 FPS，不是受控性能对照；请求 1024×768 窗口时 16:10 内容为 1024×640，报告已区分窗口与像素。
